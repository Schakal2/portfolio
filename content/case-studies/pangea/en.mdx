## 01 · Where the idea comes from

I make music on grooveboxes. Every device does one thing brilliantly and fails at another. Pangea is meant to close that gap: **a PO-33 that does what the KO II can't — with the multiplayer of Figma.**

## 03 · Foundation first

A music app only feels light if it never drifts out of time. So I built the core first, with rules that guarantee it: the audio hardware owns the clock, positions are integer ticks, every change can be undone, and devices sync absolute facts through my own server.

![Engineering principles](/images/pangea/d03-architektur.png)

---

## 04 · Then came the problem

By late October almost every feature worked: sampler, slicer, tape, mixer, sync between phone and laptop. But each new feature had been **squeezed** into the interface. On the phone it was barely usable.

On 27 October I flipped the order: **feature freeze**. From then on, design comes before code — following the Double Diamond, with a complete UX/UI case for each area.

## 07 · The guiding feeling: lightness

The conga rule: real congas, really played — they turn funny only through the song's tempo. **Real in behaviour, one exaggeration in form.** Ten principles follow from that, ranked by weight: haptics, character, toy first, little that fits, the first level teaches …

![Lightness, the conga rule and ten principles](/images/pangea/d09-prinzipien.png)

### Haptics as a system

Weight and snapping can't be painted. So motion and sound are **tokens** in the design system — six words with fixed durations and meanings: press, snap, spring, pulse, wiggle, land.

I studied **how** the Game Boy draws: 8×8 tiles, four tones, three layers. A DAW can be built exactly like that — grid as background, bars as window, clips as sprites.

## 11 · Working with AI

I tried to automate the process with a chain of AI agents: Telegram → UX agent → Figma agent → code agent. It was instructive — above all about what **can't** be automated. A single vault as source of truth, one file per decision and a review entry per branch held up. Restarts overwriting decisions, and tests checking buttons instead of flows, did not.

![Agent chain — what held, what broke](/images/pangea/d14-agenten.png)

---

## 12 · What I learned

- **Design before building.** Features that exist before their flow have to be taken apart later.
- **Tests must check stories**, not buttons. A test following a user story would have revealed the squeezed interface much earlier.
- **Discarding is progress.** Chrome and texture were necessary to know why pixel is right.
- **One source of truth.** Every decision as its own file — otherwise the next run overwrites it.
