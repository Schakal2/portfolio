## A store nobody dared to touch

meinTee sells tea sets and gifts, with a configurator for engraved sets. Over time the Shopify theme had picked up many small issues: product images cut off under the header, a review form in the wrong tone of voice, a cart that opened before the product was in it.

None of them was big. Together they made the shop feel unreliable, and because the local code no longer matched what was live, every fix risked breaking something else.

---

## A five-step routine for every change

Before fixing anything, I set up one fixed workflow. Every change, however small, went through the same five steps.

1. **Pull the live theme.** Download the code straight from the live store, so it matches what customers actually see.
2. **Compare.** Diff every file against the original theme and note what changed and why.
3. **Test in the browser.** Prototype each fix in DevTools on the real store before touching a file.
4. **Mark it.** Tag every custom change in the code so it can be found again after theme updates.
5. **Ship one file.** Upload a single file at a time, after checking that nobody else changed it.

---

## Four fixes, before and after

Each fix followed the same pattern: what was wrong, why it happened, and what I changed.

### The gallery that slid under the header

Scrolling a product page pushed the images under the sticky header and cut them off. The gallery did not know how tall the header was. It now keeps exactly as much space as the header takes up.

![Product page before and after: the gallery now stays below the sticky header](/images/meintee/fix-gallery.jpg)

### A verification page that looked foreign

After the contact form, Shopify sometimes shows a captcha page. Shopify renders this page itself and the theme had never styled it, so it looked like another company's site. Brand colours, a beige card and a rounded button now make it part of meinTee.

![Captcha page before and after, now in the meinTee look](/images/meintee/fix-captcha.jpg)

### A cart that opened too early

After "Add to cart" the drawer slid open before the product was in it, because the theme did not wait for Shopify. The cart now waits until the item is really added, with a check mark on the button in between.

![Mobile: check mark on the button right after the click, then the cart opens with the product](/images/meintee/fix-cart.jpg)

### A review form in the wrong voice

meinTee talks to customers informally. Only the review form used the formal German "Sie", and the review app does not allow these texts to be edited. A small script swaps all 71 strings before the app renders them. The form now matches the brand and can be closed.

![Review form before and after](/images/meintee/fix-reviews.jpg)

Also shipped: a Safari hover bug, a homepage video that no longer shifts the layout, category names in the mobile menu that are real links, an accessibility widget that moves above the sticky buy bar, and a home screen icon.

## Beyond fixes: a logo that assembles itself

Next to the fixes I built something new for the header. I split the meinTee mark into three SVG layers and animated them with CSS keyframes only, no library. Editors can switch it on or off, play it once per session and set all three colours in the theme editor.

![Animation timeline: star 4.0 s, leaves 2.1 s, rings 2.6 s](/images/meintee/logo-timeline.jpg)

## Takeaways

- **Get the real source first.** Working on an outdated copy cost me days. Now the first step is always pulling what is actually live.
- **Test on the real thing.** Prototyping in the browser shows the bug on the live store without breaking anything.
- **Documentation is part of the fix.** Because every change is marked and explained, the work survives theme updates and the next person can follow it.
